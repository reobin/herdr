---
title: Unified sidebar
description: Use one tree for workspaces, tabs, and panes instead of the split spaces and agent lists.
---

This page describes the `reobin/herdr` fork, which tracks upstream
`herdrdev/herdr` and adds only this layout. `herdr update` installs upstream
binaries, so it reverts this sidebar. To keep the unified layout, run a
source build of the fork instead:

```bash
git clone git@github.com:reobin/herdr.git
cd herdr
cargo build --release --locked
```

Then put `target/release/herdr` on your `PATH`:

```bash
chmod +x target/release/herdr
mv target/release/herdr ~/.local/bin/herdr
```

Set `ui.sidebar.layout = "unified"` to replace the split sidebar with a single tree. The default `"classic"` keeps the spaces list and agent panel as separate sections.

```toml
[ui.sidebar]
layout = "unified"
```

## What the tree shows

Each workspace block opens with its name, lists its panes, and closes with a footer marking the git branch in the spine column (`◇ main`), with ahead/behind counts at the right edge, for every workspace including linked children. A workspace without a branch has no footer, and its spine runs straight down. The name is the repo, or the label followed by the repo in tertiary when the workspace is renamed (`manifest-order  ordering-web`); the repo truncates before the label does. The repo resolves through linked worktrees, so a checkout at a different path still shows its repo; outside a repo it falls back to the directory name. The name stays primary and turns bold on focus or selection, since pane rows already carry status. The footer stays quiet in every state. One blank row separates workspace blocks.

A spine runs down each block beside every tab, pane and summary row, in every tab of every workspace, so the column never breaks between focused and background states. Workspaces with two or more tabs show one header row per tab: the tab name, then a hairline rule to the edge. A lone tab skips its header. Tab names and status glyphs share the column past the spine; summaries sit under the pane label. The spine stays solid from the top through the selected tab and fades past it. The selected tab's name goes bold; other tabs' names, rules, summaries and spine fade to dim tertiary, though the navigate cursor still lifts their summaries. The navigate cursor fills its block with the selection background. The focused pane of the focused workspace sits on a band in the active row color, the full width of the block and across its summary too; the band is the only focus fill, so the focused block itself stays unfilled. A parked focused workspace keeps the fill on its single row.

Each pane row shows its status glyph and the `[ui.sidebar.agents]` row text flattened into one line. Working panes animate through a braille spinner; blocked and done panes show a filled dot, told apart by color; idle panes show a hollow ring; shells show a middle dot. These glyphs belong to the unified layout; classic layout keeps its configured dots or symbols. Agent titles and glyphs keep their signal hue in every tab, losing only bold: working, blocked and done agents stay yellow, red and green, while the focused pane goes primary and bold. The `state_icon`, `machine`, `workspace`, and `tab` tokens are dropped because the tree already shows them. With the default rows, an agent pane takes two lines: the session label with the harness after it a step quieter on the first, for example `herdr pi`, and the reported `$summary` on the second. The second line is reserved whenever the rows include `$summary`, so rows never shift when a summary arrives. A custom layout without `$summary` keeps agent panes to one line. A summary steps up to secondary without bold only for the focused pane or under the navigate cursor. Shell panes without an agent take one line showing the callsign, falling back to `shell`. An agent's first row also carries its time in the current status right-aligned (`45s`, `12m`, `1h23m`), restamped on every status change; the label truncates first, and the slot gives up on narrow rows.

Click a pane row to focus it. Parking a workspace folds its block to a single row with just the name, keeping the workspace open without its vertical cost; park and unpark from the keyboard as below. A parked workspace's name takes the hottest pane status color (red while blocked, yellow while working, green when done), so it still reports at a glance. Parked workspaces persist across restarts with the other sidebar collapse state. Clicking a header focuses the workspace. When the sidebar is collapsed in unified layout, it shows workspaces only.

## Parking workspaces from the keyboard

There is no default key: parking from the keyboard is opt-in through the stock `[[keys.command]]` extension point with the sentinel command text below. Bind any prefix key; `prefix+m` is just the example.

```toml
[[keys.command]]
key = "prefix+m"
command = "unified:toggle-workspace-park"
```

The sentinel is consumed client-side before custom-command dispatch, so it never runs as a shell command and never needs an endpoint round trip. The key must use prefix form (`prefix+m`, not a bare or modified key): anything else never reaches the intercept and runs as a normal command. `type`, `width`, and `height` are ignored; `description` only feeds the help overlay entry, so describe the parking there. Only the local keymap can trigger it: remote or endpoint keymaps strip custom commands, sentinel included. A real action binding on the same key still wins through the existing resolve order, but do not reuse a sentinel key for another custom command. Spell the key canonical lowercase (`prefix+m`); other spellings of the same key may stop matching once the endpoint round trip replaces the command text. The key toggle is inert in classic layout and in the collapsed rail, and it shows up under the help overlay's custom section.

## What unified layout ignores

In unified layout, `[ui.sidebar.spaces]` `rows` and `row_gap` plus `ui.sidebar.agents.row_gap` still parse but have no effect. `agent.view.set` still drives the mobile Agents list and agent navigation, just not the expanded sidebar. See [Configuration](/docs/configuration/) for the stock sidebar layouts this replaces.

## Why this is a fork setting, not a plugin

Upstream [plugins](/docs/plugins/) are workflow packages built on manifest
actions, event hooks, and terminal panes. Native non-terminal plugin UI is not
part of plugin v1, so no plugin can replace sidebar rendering today. For this
layout to become a plugin one day, upstream would need a sidebar render and
layout hook, a pane hit-test and click hook, a `ui.sidebar.*` config-schema
hook, and the pane and agent facts this layout already reads from the
CLI/socket API. None of that is built here.
