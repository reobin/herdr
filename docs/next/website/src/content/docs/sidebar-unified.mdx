---
title: Unified sidebar
description: Use one tree for workspaces, tabs, and panes instead of the split spaces and agent lists.
---

This page describes the `reobin/herdr` fork, which tracks upstream
`herdrdev/herdr` and adds only this layout. `herdr update` installs upstream
binaries, so it reverts this sidebar. To keep the unified layout, run a
source build of the fork instead:

```bash
git clone git@github.com:reobin/herdr.git
cd herdr
cargo build --release --locked
```

Then put `target/release/herdr` on your `PATH`:

```bash
chmod +x target/release/herdr
mv target/release/herdr ~/.local/bin/herdr
```

Set `ui.sidebar.layout = "unified"` to replace the split sidebar with a single tree. The default `"classic"` keeps the spaces list and agent panel as separate sections.

```toml
[ui.sidebar]
layout = "unified"
```

## What the tree shows

Each workspace gets a fixed header and pane rows below it instead of a group bar: tabs align with the header and panes indent two spaces under their tab, with summaries under their pane. A quiet spine hangs below each tab name across the full height of its pane rows, so each tab reads as one block. The navigate cursor fills its block with the selection background. The header name stays primary in every state and turns bold on focus or selection, while the branch line stays quiet in every state. Unfocused tabs and panes sit with the branch line too; the selected tab goes primary without bold; only an agent that is working, blocked, or done steps up to secondary, while the focused pane goes primary and bold. A summary steps up to secondary without bold only for the focused pane or under the navigate cursor. The header shows the repo name, plus ` / label` when renamed, with both sides in primary (bold on focus or selection) around a quiet divider, then the git branch with ahead/behind counts for every workspace including linked children. The repo resolves through linked worktrees, so a checkout at a different path still shows its repo; outside a repo it falls back to the directory name. One blank row separates workspace blocks.

Inside each workspace, panes group under per-tab sections. Each pane row shows its status glyph and the `[ui.sidebar.agents]` row text flattened into one line. Working panes animate through braille spinner frames, blocked panes show a diamond, done a check, idle a dotted ring, and unknown a middle dot. The dotted idle echoes the spinner's texture, so settling into idle reads as a texture shift rather than a shape collapse. These glyphs belong to the unified layout; classic layout keeps its configured dots or symbols. The `state_icon`, `machine`, `workspace`, and `tab` tokens are dropped because the tree already shows them. With the default rows, an agent pane takes two lines: the session label and harness on the first, the reported `$summary` on the second, for example `herdr · pi` with `refactor auth` below it. The second line is reserved whenever the rows include `$summary`, so rows never shift when a summary arrives. A custom layout without `$summary` keeps agent panes to one line. Shell panes without an agent take one line showing the callsign, falling back to `shell`, without a kind prefix: the dim `$` where agents show their status glyph already marks them as non-agent rows. An agent's first row also carries its time in the current status right-aligned (`45s`, `12m`, `1h23m`), restamped on every status change; the label truncates first, and the slot gives up on narrow rows.

Click a pane row to focus it. Click the `≡n` count at the right edge of a workspace header to park it: the block folds to a single row with just the name and the count, keeping the workspace open without its vertical cost. Click the count again to expand. The count shows the pane total and takes the hottest pane status color (red while blocked, peach while working, green when done, quiet otherwise), so a parked workspace still reports at a glance. Parked workspaces persist across restarts with the other sidebar collapse state. Clicking anywhere else on the header focuses the workspace as before; only the count toggles. When the sidebar is collapsed in unified layout, it shows workspaces only.

## Parking workspaces from the keyboard

There is no default key: parking from the keyboard is opt-in through the stock `[[keys.command]]` extension point with the sentinel command text below. Bind any prefix key; `prefix+m` is just the example.

```toml
[[keys.command]]
key = "prefix+m"
command = "unified:toggle-workspace-park"
```

The sentinel is consumed client-side before custom-command dispatch, so it never runs as a shell command and never needs an endpoint round trip. The key must use prefix form (`prefix+m`, not a bare or modified key): anything else never reaches the intercept and runs as a normal command. `type`, `width`, and `height` are ignored; `description` only feeds the help overlay entry, so describe the parking there. Only the local keymap can trigger it: remote or endpoint keymaps strip custom commands, sentinel included. A real action binding on the same key still wins through the existing resolve order, but do not reuse a sentinel key for another custom command. Spell the key canonical lowercase (`prefix+m`); other spellings of the same key may stop matching once the endpoint round trip replaces the command text. Like the count click, the key toggle is inert in classic layout and in the collapsed rail, and it shows up under the help overlay's custom section.

## What unified layout ignores

In unified layout, `[ui.sidebar.spaces]` `rows` and `row_gap` plus `ui.sidebar.agents.row_gap` still parse but have no effect. `agent.view.set` still drives the mobile Agents list and agent navigation, just not the expanded sidebar. See [Configuration](/docs/configuration/) for the stock sidebar layouts this replaces.

## Why this is a fork setting, not a plugin

Upstream [plugins](/docs/plugins/) are workflow packages built on manifest
actions, event hooks, and terminal panes. Native non-terminal plugin UI is not
part of plugin v1, so no plugin can replace sidebar rendering today. For this
layout to become a plugin one day, upstream would need a sidebar render and
layout hook, a pane hit-test and click hook, a `ui.sidebar.*` config-schema
hook, and the pane and agent facts this layout already reads from the
CLI/socket API. None of that is built here.
